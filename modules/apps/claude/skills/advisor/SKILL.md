# advisor — Fable によるセカンドオピニオン

**役割分担**：本体（日常セッション＝Opus）が論点を確定させ、Fable **1体**に判断だけを投げ、
返ってきた意見の採否を本体が決める。Fable は「メインでは使わない・判断の単発委譲でだけ使う」
という前提の唯一の入口がこのスキル。

`~/.claude/settings.json` の `permissions.ask` に `Agent(model:fable)` があるので、起動時に確認が
1回出る。これは想定どおり（fan-out で Fable が偶発的に増殖する事故を止めるためのゲート）。

## 呼ぶとき / 呼ばないとき

**呼ぶ**：選択肢が2つ以上あって甲乙つけがたい設計判断／取り消しにくい決定の前／本体の案に
自分で穴を見つけられないとき／同じ論点を2ターン以上ぐるぐるしているとき。

**呼ばない**：事実調査・情報収集（→ sonnet サブエージェント）／機械作業（→ haiku）／
もう決まっている話の追認／「どっちでもいい」レベルの選択。**迷いの実体が情報不足なら、
先に調べる。advisor は情報の代わりにならない。**

## 手順

### 1. 先に論点を確定させる（本体の仕事）

以下が書けないなら、まだ投げない。書けないこと自体が「調査が足りない」の合図。

- **決めること**（一文。「AとBのどちらを採るか」の形）
- **選択肢**（2〜4個。それぞれ1〜2行）
- **制約**（期限・可逆性・依存・触ってはいけないもの）
- **検証済みの事実** と **前提（未確認）** を分けて書く（AGENTS.md の回答規律と同じ形）
- **本体の暫定推奨**（あえて先に出す。Fable に穴を突かせるため）

### 2. 文脈は本体が貼る（探索させない）

サブエージェントは新規コンテキストで立ち上がる。**必要なファイルは本体が読んで抜粋を
プロンプトに貼る**。「リポジトリを見て判断して」と丸投げしない — Fable に探索ループを
回させるのがいちばん高くつく。

### 3. Fable を1体だけ起動

Agent tool を次の指定で呼ぶ：

- `subagent_type`: `"Plan"`（既定。read-only なので誤って書き込まない）
  ファイルを一切読まない純粋な判断なら `"general-purpose"` でもよいが、その場合は
  プロンプトに「ファイルを変更するな・読むだけ」と明記する
- `model`: `"fable"`（**必須**。無指定だと本体モデルを継承して意味がない）
- `run_in_background`: `false`（判断を待ってから次に進む）
- **1論点1体。並列起動もリトライループも禁止。**

プロンプトの型：

```
あなたは設計判断のセカンドオピニオン。実装はしない。判断だけを返す。

## 決めること
<一文>

## 選択肢
A: ...
B: ...

## 制約
- ...

## 検証済みの事実
- ...

## 前提（未確認）
- ...

## 依頼元の暫定推奨
<本体の案と、その理由>

## 参考（依頼元が抜粋した資料）
<ファイル抜粋・ログ・仕様など>

## 返してほしい形式（これ以外を書かない）
1. 推奨：どれか1つ。曖昧に濁さない
2. 理由：3行以内
3. 捨てた選択肢：それぞれ1行で「なぜ捨てたか」
4. 依頼元の暫定推奨の穴：見つからなければ「無し」と書く
5. この推奨が崩れる条件：どの前提が外れたらひっくり返るか
```

### 4. 受け取った後（本体の仕事）

- **丸投げしない。** 採るか採らないかは本体が決め、ユーザーには「advisor の推奨」と
  「本体としての結論」を1メッセージで示す。両者が割れたなら、割れたこと自体を書く
- **同じ論点で2回目を投げない。** 1回で決まらないなら、足りないのは意見ではなく情報か
  ユーザーの意思決定。調べるかユーザーに聞く
- 恒久的な決定になったなら vault に保存する（claude-obsidian なら save / para-project、
  他プロジェクトからは `vault/.raw/inbox/` に捕獲メモ）

## やらないこと

- Fable をメインセッションのモデルとして使う運びにしない（このスキルは委譲専用）
- Fable サブエージェントに実装・編集・長時間の作業をさせない（作業は sonnet）
- 複数体の Fable を並べて多数決を取らない（1体・単発が規律）
